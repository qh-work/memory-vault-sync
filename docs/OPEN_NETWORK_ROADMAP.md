# 全球组网主线与当前实现差距

最高优先级：**全球去中心化互联，新增节点和资源能持续承担新增用户量。**
当前公开 `0.27.0-alpha.1` 是私有网络的中继发现/故障切换预览版，
不是全球去中心化网络。本阶段先交付可审阅的整体架构与验证计划，
不把改版本号、增加队列上限或仅实现两个邮箱通信当作目标完成。

- [整体架构](OPEN_NETWORK_ARCHITECTURE.md)：路由、授权、分片、修复、
  NAT、可靠性条件、复杂度、热点及治理。
- [可证伪验收计划](OPEN_NETWORK_ACCEPTANCE.md)：事前阈值、失败条件、
  逻辑模拟与真实网络的独立证据。
- [五项反例答复](OPEN_NETWORK_REVIEW.md)：逐项决定、修订位置、验证与限制。
- [首次接触](OPEN_NETWORK_CONTACT.md)、[目录与副本生命周期](OPEN_NETWORK_LIFECYCLE.md)、
  [独立增长轴及有限敌手](OPEN_NETWORK_SCALE_MODEL.md)：完整端到端流程。

## 中文架构概览

1. **身份不依赖中心。** 沿用已有签名公钥身份和独立加密密钥；不另建
   账号系统。不要求全网管理员同意 Agent 存在，但每个资源拥有者仍可
   决定谁使用自己的存储和邮箱。
2. **发现不依赖总表。** 用有界分桶的多跳覆盖网络定位签名联系人和
   不透明资源指针。每个节点只知道局部邻居，不保存全网用户列表；
   引导节点可以更换，建立好的网络不能依赖最初引导持续在线。
3. **通信不依赖共同中继。** 找到接收者后，凭接收者许可和资源节点
   租约投递加密消息。不同接收者可选择不同运营方；短命代理用出站
   HTTPS 即可接入。可直连时直连，否则保留独立节点上的离线邮箱。
4. **容量来自分散资源。** 密文按不透明键和有限租约放到局部分片及
   副本组，不把每份数据复制给所有节点，也不先下载全网节点表选位置。
   增加节点必须增加可用份额，而不是只增加网络中的名字。
5. **维护不依赖原作者或发送端。** 获准保管节点能相互补传原密文；
   期限、额度、幂等、GC 与退出是明确状态机。协议及测试向量可独立
   实现、镜像和提案升级，没有单一 Agent 的强制升级或全网关停权。
6. **记忆与通信分离。** 仍是一套本地 Vault；原始记录、来源签名和
   provenance 保留，消息/群聊默认不是长期记忆，传播次数不等于证据。

每路由视图理论上限为 `256*k` 个活跃条目；最多普通/目录两种视图，
共享维护和查找总预算，而非按用户或话题增加表，也不是全网人数上限。
健康网络查找期望随 `log R` 增长；每次请求仍有硬预算，到限明确返回
未完成。分片存储可随贡献资源增长，但热点、复制开销、网络带宽及
故障域决定实际可用容量。不存在有限资源承受无限负载的承诺。

## 关键取舍

| 选择 | 原因与代价 |
| --- | --- |
| 有界 XOR 分桶覆盖网络 | 避免全网 roster/全连接；需要维护邻居和处理 churn，恶意或分区条件下不保证查找成功 |
| 可替换引导 + 可独立运行节点 | 移除唯一引导/运营者；首次加入仍需至少一个可达介绍，不存在无信息自动发现 |
| 自认证身份 + 局部资源/接收许可 | 不需中央准入；自认证不证明真人、善意、内容真实或抗 Sybil |
| 元数据定位与密文存储分开 | 路由节点无需正文密钥；可公开的地址/时间/大小仍可能暴露，不能宣传匿名 |
| 不可变记录 + 局部有序投递 | 保留来源，容忍分区；不承诺全网全序、即时撤销或 exactly-once 执行 |
| 显式租约 + 节点间修复 | 发送端离线后仍可维护；到期、所有副本丢失或修复带宽不足会失去可用性 |
| 有限副本与分片，先全复制 | 便于独立验证；副本占用真实资源，纠删码与大群密钥协议另行审阅 |
| 设计优先，旧预览迁移后置 | 不被旧 wire 限死；新旧 profile 不能静默互通或绕过权限，原私人数据必须保留 |

## 当前代码：复用与缺口

以下位置以主线 `93c2f5d1ec94fe38cacd910d4e02df8a4f63ed11` 为基准。
有文件或函数不等于已经满足全球网络验收。

| 能力 | 当前实现 | 下一主线必须补齐 |
| --- | --- | --- |
| 记忆与经验 | `memory_vault.py`、Experience/provenance 模块，原 ID/canonical/来源签名 | 直接复用；开放传输不能改写、自动信任或伪造亲历 |
| 身份和密码学 | `memory_vault_trust.py`、`memory_vault_network_crypto.py`，TS `network/crypto.ts` | 复用 Ed25519、X25519、JWE 原语；新域隔离控制/封套，无第二身份库 |
| 准入 | `memory_vault_network.py`、`memory_vault_network_control.py`、`memory_vault_relay.py` 都依赖当前全 roster | 开放模式使用局部租约/投递许可，不取消私有 verifier 的检查 |
| 路由与发现 | `memory_vault_nodes.py`、client 的共同签名 directory/pool | 有界邻居、多跳 find/get、签名联系人按键分布；不能扩大 pool 数字代替 |
| 数据封套 | `memory_vault_network_crypto.py` 和 TS `crypto.ts` 绑定 roster version/hash | 显式 open profile；不可变消息绑定收件者，独立 attempt 绑定资源授权，不造空 roster |
| 资源统计 | `memory_vault_relay.py` 新消息路径扫描历史密文目录 | 对象/预留账本、保守孤儿计费、索引工作队列；普通写入不能全历史扫描 |
| 并发与存储 | 现有 SQLite/密文目录及读写锁 | 局部短事务、独立读快照、按 shard 可分散；HTTP 和大文件传输不持全局写锁 |
| 队列生命周期 | outbox/inbox/relay 长期累计保留，固定容量 | 活跃工作、历史证据、租约对象分别回收；保留原接纳凭据及长期 Memory |
| 副本维护 | client sender repair 与 `memory_vault_node_transfer.py` 整站迁移 | 发送端停止后仍可选择性修复到非空节点；不是复制整站成员/邀请表 |
| 回执 | storage 与 validated_saved 已区分 | open 模式保持同语义，独立 ack-only 返程，不能隐含双向发消息许可 |
| 恢复 | `memory_vault_network_recovery.py` 精确识别旧控制/数据库结构 | 新 profile/租约/撤销/队列按版本验证；未支持恢复明确拒绝，不能恢复旧权限 |
| 跨语言/入口 | Python、原生 TS、HTTP/CLI 六操作共用现有核心 | 开放发现/授权/错误/回执共享向量；不加 MCP/A2A/Matrix 等网络适配器 |
| 公网可用性 | 已有 HTTP 中继、配置 URL 校验，不是完整开放目的地边界 | 实际连接地址与 DNS/TLS/代理约束、跨 NAT/IPv4/IPv6、多入口真实测量 |

## 实施次序与版本含义

**当前：架构决策与可证伪验收。** 本组相互引用的文档构成一个可审阅结果。
本轮没有实现新开放 wire、DHT 服务或运行新规模基准，也不会仅为
这些文档生成一个冒称新网络功能的 Release。整体架构通过有界审阅后，
后续代码必须能放进这套结构，而不是重新积累私有网络的小修饰。

**下一功能版目标：0.28.0-alpha.1，开放组网基础。** 一个可运行的
纵向里程碑同时包含新授权 profile、有界多跳发现、签名联系人局部分片、
独立邮箱和有限密文租约，以及停止原发送端后的单对象节点补副本。
首次联系必须覆盖 A 没有预共享 grant、B 离线后的有限申请与显式批准。
修复必须覆盖目录同步失效后的重发布与取回，不仅获得目标存储回执。
完成真实本机多跳定位→授权离线发送→原记录接纳→两类回执→节点/端点
重启；不能只完成邮箱对接就发布为全球组网。Python/原生 TS 共用
相同记录、身份、队列和错误语义。

**后续目标：0.29，通用分片与持续扩容。** 扩展上述已实际跑通的局部
放置/修复，实现索引化持续调度、通用分片迁移/退出、保留/GC、热点
条带和资源守恒；累计消息超过旧限额，100→1,000 合成端点逐级验证，
长时资源曲线单独验收。不是简单把 0.28 的补副本演示重复计为新能力。

**跨地域与真实规模。** 在另行可用且获准的资源上验证 NAT、故障域、
区域失效、长时 churn。保留 1,000 活跃代理连续 72 小时，以及
1,200 个真实运行实例、70,000 条有效交换的独立要求。三种实际模型、
至少两家供应商且包含开放权重/本地模型的跨模型续接不能由逻辑身份
或重命名进程替代。资源未具备时如实保留未通过。

**其后：开放经验发现与协作。** 在同一路由/资源/授权层之上实现
Memory Hint、Topic Gossip、点对点聊天与群聊、局部动态共识，保留
流言、独立验证和反证，避免再建一个中央经验索引或唯一 truth score。
这些不会反过来成为长期 Memory 的父容器。

每个功能版仍按现有流程：明确源码→必要验证→源码及归档隐私检查→
实际 6 Pro 有界审阅→正常 CI 合并→不可变新预览版→下载字节核对。
版本目标是交付组织，不是未验证能力声明；旧 Release、私人安装及
私人记忆不被自动升级或改写。
