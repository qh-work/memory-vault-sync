## 目标和判定原则

最高优先级是全球互联、去中心化、随新增节点与资源横向扩展。
“无限增加用户”落实为没有固定全网人数或容量配额、不要求全网同步，
而不是有限设备承担无限请求。测试必须能推翻扩容假设，不能只展示两个
预配好地址的客户端通信成功。

必须分别报告：设计推导、纯逻辑模拟、真实 HTTP 进程、独立主机/地区、
真实模型/代理和长期运行。任何一层通过都不能替代其他层。下面的阈值
是事前验收目标，不是当前能力声明；失败后可修改设计并解释，不得更换
有利种子、删除失败案例或悄悄降低阈值。

可靠性是有条件的：存在可达且诚实的授权资源、至少一份完整可用副本、
所需密钥未丢失、租约尚有效，而且长期处理速度大于到达速度。
永久网络隔离、所有副本丢失、全部引导源被控制、无限攻击流量，不在
无条件可用性保证内。这些情况仍必须保持权限、资源和诚实状态边界。

## A. 不依赖全网视图的增长实验

每个模拟节点使用生产路由算法，只能访问自己的路由表和传输接口。
测试驱动可保存完整拓扑用于断言、地址投递和故障注入，但不得为节点
挑选全局最近邻、预装全量联系人、直接查全局记录或代理完成最短路。

1. 节点逐个从最多两个既有入口加入。通过实际模拟请求学习邻居，
   每轮只执行有预算的维护。不提供全网成员 API。
2. 分别在 100、250、500、1,000 节点完成后，每个固定种子执行
   1,000 次合法查找，覆盖至少 20 个源，事先固定源/目标集合。
   健康均匀地址场景，在事先规定的 20 轮有界维护后，目标发现成功率
   应至少 99%；至少一组路径必须查询一个其地址/身份首次从上一轮
   回复得到的节点，再由该节点取得后续路径或目标；该节点不得来自
   初始候选或全局夹具。两个已知入口各问一次不算多跳。目标最初不在
   发起者的路由表。失败必须保留原因及路径。
3. 每节点路由表、替换区、连接、查找候选、请求数及响应字节均不能
   超过合同上限。不允许靠扩大候选队列来通过更大规模。
4. 绘制全部规模的成功率、实际请求、因果轮次和耗时分布。
   100→1,000 的健康成功率下降不超过 2 个百分点，成功子集请求
   p95 增量不超过 12、因果轮次 p95 增量不超过 3、耗时 p95 不超过
   原值两倍加 100 ms；固定链路模型及失败统计见增长合同。
   64 次硬预算另行约束，不能拿等于硬上限的公式当增长门槛。
   有限规模点不能证明渐近复杂度；快速拒绝不能降低失败罚分。
5. 新增一台节点必须不要求所有旧节点写入它、同步 roster version
   或停机。记录每次加入实际触达和写入的节点数；若存在全网广播
   或每节点完整成员表，结构性验收直接失败。
6. 移除全部最初引导入口，已建立网络成功率仍应至少 97%；新节点使用另一个
   既有成员加入。若没有任何可达介绍，正确结果是孤立，不能伪造发现。

同时运行稀疏/聚集前缀、单来源介绍、重复候选、循环引用、错误签名和
恶意超大回复。攻击场景按增长合同单独锁定资源和目标：指定 10% 有限
敌手下至少 95% 成功、每目标至少 80%，不能因目标被围困就从分母删除。
25%/40% 或四倍洪泛另报压力边界。单纯安全拒绝不能计为正常可达成功。
还必须独立增长 A≫R、身份 churn、资源 churn、在线率、业务到达率、
保留期和租约续发；不能只让身份数与资源数同步增加。
目录角色还需独立变化 Rd/Rr=1、.1、.01：让普通视图最近的 8 个节点
全不提供目录，仍必须通过有限目录引介进入角色视图并按同一规则
写入/冷读取。所有阶段共享一次总预算，不能建立全网角色表或顺序扫遍
普通节点。未获得实际目录租约必须报告资源不足。

## B. 总资源增加是否带来实际容量

逻辑提供方增长配对采用 16→32、64→128、256→512，每节点使用相同
配额 `B`；1,024 作为另一个容量点，资源允许才运行。副本目标 `r=3`。
有效基准容量先扣除约定的预留/元数据/修复空间，再除以 `r`。
先以总有效容量的 40% 提交大小/散布固定的对象；
节点算法通过有界查找取得候选，再向具体节点申请实际租约，不能遍历
全部节点挑空闲空间。

固定原负载，再逐步增加提供方和新负载。分别记录：

- 唯一对象量、真实/模拟副本字节、暂存/孤儿/元数据开销、实际可用余量。
- 每节点占用的均值、p95、最大值和拒绝率，不只报告全网平均。
- 资源加入后的有用数据/请求份额，迁移/修复字节与新节点承担的负载。
- 本地索引数量和查找路径，不允许新增节点后仍由老节点保管全部对象。

健康均匀场景中资源翻倍并投入相同比例新负载后，在固定的 20 轮维护
内，接受的唯一数据量应至少达到原来的 1.6 倍，且所有本地硬配额保持
不变、p95 单节点占用不超过配额。未达到就说明放置/路由/负载均衡
存在问题，不能宣称横向扩容成立。该门槛不是任意热点下的线性保证。
成功容量只统计已有三个有效租约和实际持久化确认的对象；降级或只有
容量广告的对象另列，不能降低副本数来提高扩容曲线。

模拟可用 digest+size 表示大对象，必须明确这不是实际存入的密文。
另以真实文件和服务验证相同资源状态机；两者不得合并成吞吐数据。

## C. 真实多跳、离线投递与两类回执

8–12 个独立本机 HTTP 节点使用各自临时身份、数据库和资源许可。
至少 A、B、C 三个逻辑 Agent 采用不同入口，不能启动 authority、
预填共同 roster 或共享固定 relay pool。

要求 A 只知道 C 的身份，不预知 C 邮箱地址。A 查询的后续节点必须
首次由前一真实响应介绍，而不是初始配置或测试 oracle，再通过该节点
取得后续路径或 C 的签名联系人；仅并行询问两个已知入口不算多跳。
首次通信还必须运行没有预共享 grant 的流程：C 主动配置独立 knock
lease/policy 后离线，随后才创建 A 身份，断言所有既有 grant 无 A。
A 经挑战取得 contact_queued；此时正式 send、Memory 和普通 ack 仍
拒绝。C 恢复自己的正常运行后明确批准，A 从请求绑定的结果槽取回
合法具体 grant；不能要求先有反向聊天权限才能取得批准。完整负例、
严格控制字段、队列满与撤销/重放在首次联系文档中逐项验收。
另从允许展示的本地候选引介发现此前完全未知的 C，不能用全局 oracle。

核对独立资源/投递授权后再执行显式发送：

1. 普通聊天；长期 Memory 数不因此增加。
2. 明确选中的原记录及全部获准依赖；原 bytes、ID、来源签名不变。
3. C 离线时节点签存储回执；C 重启后独立校验并保存，再签接收回执。
4. 回执使用 A 单独授予 C 的 ack-only 返回权限。只有该权限时，
   任意聊天、查询、Memory 上传和回执递归必须被拒绝。
5. Python→TypeScript 和 TypeScript→Python 使用真实已有 JOSE。
   禁止密码替身、空 roster、测试专用绕权开关。

共享原始报文字节的负例另做两语言矩阵：重复字段、未知/混用 profile、
错误 type/audience、bool 或不安全控制整数、Unicode 与签名输入边界、
错误算法/曲线/收件者。比较错误码与拒绝后的无副作用，不仅比较成功
互通；现有 Memory/Experience 完整 int64、canonical、签名向量不变。
原授权过期后，以显式新授权创建签名投递 attempt，验证同一密文可以
转向获准新租约，而旧 attempt、未授权新节点和新增解密收件者仍拒绝。

新增一个邮箱和资源节点，无需修改其他 Agent 的全网配置；删除最初
引导后仍完成上述流程。每个真实节点仅看到局部控制状态和密文。
多个本机端口仍只算一个物理故障域，不是跨地区验收。

## D. 发送端离线后的副本修复

本节的正例必须从消息产生前冻结接收者 B 的持久状态：只含当时的
身份/密钥、邮箱锚点 `K_B`、既有路由引介与预先有效的授权。先记录
该快照的摘要与允许输入清单并停止 B，然后 A 才创建并发送新消息 m，
之后 A 完全停止。B 未见过 m，不能把发送后的收件箱/缓存或更新后的
备份放回 B。原本需要实时批准的权限，不能借此测试被提前或自动授予。

在三个有效租约提供方保存密文及合同要求的加密枚举元数据后注入故障，
由存活保管节点把对象和必要枚举链补到**已有其他数据的**新节点。
目标分别验证对象/元数据、来源/目的地、epoch/期限、有限委托和容量。
枚举成员证据必须绑定原始投递 attempt/grant，保留不可变原文和签名；
修复者只能复制获准证据，不能新造邮箱成员关系、写者权限或收件人。
不得导入全站成员表，不得调用 A 重发，也不得要求目标为空。

使全部原邮箱、枚举元数据和密文持有者不可达，再从上述旧快照启动 B。
B 必须从 `K_B` 通过真实协议依次发现有限写者/feed 命名空间、获准
分段/页及成员证据，进而发现 m 和对象位置，并读回原 bytes/ID/签名。
测试驱动可断言和注入故障，不能向 B、其客户端或代查节点注入 m 的
message ID、对象键 `K_m`、segment/page ID、新地址或新成员目录；
这些值只能来自实际协议响应，记录每项首次出现的来源。仅清缓存后把
已知 `K_m` 交给 B 调用读取，不是离线消息发现验收。

分别报告，禁止用一个 USABLE/成功计数互相替代：

| 状态 | 必须有的证据 |
| --- | --- |
| `object_readable` | 给定合法对象引用和读取权限，能够读回完整原密文；不证明 B 知道消息存在。 |
| `message_discoverable` | B 从消息产生前的 `K_B` 与既有权限实际枚举到 m，验证其原始成员/投递证据；不能预知 m 或 `K_m`。 |
| `validated_saved` | 实际 B 解密、校验并完成约定本地保存后签收；前两项不代替此状态，聊天仍不自动写长期 Memory。 |

端到端正例必须完成三项；对象保管层的 USABLE 只能声明对象可读。
外置保管授权不改 JWE，也不自动给予新节点邮箱投递或枚举扩权。

必须保留三个可区分的负例：

- 只修复密文和 `K_m` provider 广告，不修复枚举链。独立诊断读者用
  已知 `K_m` 实测 `object_readable`，但不能把这个键传给冷 B；B 从
  `K_B` 应报告消息发现不完整。不能凭诊断读取成功计端到端修复成功。
- 元数据修复/重发布委托到期，而密文租约仍有效。拒绝无权续发的元数据，
  B 得到 expired/incomplete；复制对象不能续期枚举权限或作者签名。
- 销毁连接 `K_B` 与新消息的全部有效枚举证据，只保留对象及其广告。
  B 必须报告当前枚举不完整，而不是空邮箱/已读完/消息不存在。只有
  测试 oracle 能确认该夹具枚举链已丢失；节点不能据超时断言全网丢失。

目标在持久化并签署回执后，才把状态从 attempted 改为 committed。
committed 仍不是端到端 USABLE。按生命周期合同完成独立路径广告回读、
当前 possession、目的地取回权限及 `K_B` 枚举可达性校验，才计可发现
消息的替代保管。目录、枚举元数据和密文的实际副本/租约分别记录；
三节点签名不等于三物理故障域。
必须组合故障：原作者与发送端离线、两份旧目录失效、目标提交后发布前
崩溃、从消息产生前状态冷启动接收者。保留 60 秒重新发现和 90 秒完整
补副本目标：前者包含 `K_B` 到新消息的全部枚举发现，后者另含对象与
必要元数据的传输/提交及可读性。枚举页、成员证据、目录回读和重试均
计入同一次总预算，不能每层、每页、每次查找重新获得 60/90 秒。
事前固定故障注入与 B 启动时点，从故障至对应目标状态累计计时，不能
等后台修复完再重置时钟；`validated_saved` 的完成时间独立记录。
报告检测、调度、对象/元数据传输、提交、枚举与广告回读耗时/字节；
未满足配置的资源前提如实失败，不能只测复制文件。新增要求仍为 NOT RUN。
全部发布委托到期的负例必须失败得诚实，不允许中继延长作者签名。
测试在写入、fsync、对象发布、元数据提交、回执丢失、GC unlink 和
额度释放各阶段崩溃。重试不能双重扣费或增加逻辑副本数；孤儿数据
未清理前仍计费。修复耗时与字节数必须包含实际传输。
另分别在对象 COMMIT 后、原始成员证据持久化前，以及成员证据已提交、
枚举指针广告前崩溃：恢复必须保留明确未完成状态并以原证据幂等续接。
只有对象已存好时不能签称消息可发现；恢复者不能补造未经授权的成员
证据来填洞。合法但尚未可枚举的对象保持保管/额度义务，不提前删源。

分区中的修复只使用预分配或绑定目的地的有限额度；不能两边重复花
一个“全球预算令牌”。仍在保留承诺期的最后副本不能因另一边口头
宣称修好而提前删除。无法安全退出时返回 draining/blocked，不能
宣布无损退出。只有测试驱动已确认销毁所有有效副本时，才能判定该
夹具无法恢复；节点自身仅超时或查找失败，必须报告不可达/未知，
不能宣称全网所有副本已丢失。

## E. 持续运行、热点与背压

区分活跃队列、传输历史和本地长期记忆。累计发送超过旧 1,024 条
outbox 和 4,096 条 relay 限制，不能靠不断抬高永久累计上限通过。
以短但明确的合成保留/重试期限，验证过期后队列、tombstone、元数据
和磁盘占用达到平台期；长期 Memory 和约定保留的本地历史不被误删。
加速时钟只验证状态机，不能替代 24/72 小时运行。

在同样少量 due jobs 下，构造 32、256、2,048 条本地历史，记录
SQL 行/VM 步数与文件打开行为。普通写入不能列举全对象目录，poll
必须索引定位 mailbox/sequence，pump 必须索引读取到期工作。
实际查询计划需有代表性数据；空库 EXPLAIN 不能代替性能验证。

热点场景把 50% 流量送往一个身份。验证有限缓存、邮箱分段/条带、
租约扩展与调度配额；过载返回明确重试/拒绝，不伪报成功，也不把修复
或 GC 永久饿死。暂停接收方、压满磁盘、用大量微小合法消息及签名
灌入时，内存、句柄、临时文件、签名校验工作都要受到本地上限约束。

已有 Hint 批次本地读取依赖原 selection/inbox：队列压缩前必须保留
独立的本地接纳凭据，重启/取消/恢复后历史仍可读，迟到不合格批次
不能因压缩获得资格。不得以删掉历史查询能力换取平稳资源曲线。

必须测试同一密文的两份独立租约先后到期，以及 GC 与新 pin/续租
并发；仍有有效义务时对象不删除。崩溃后孤儿字节仍保守计费，物理
删除与目录持久化完成前不能释放可重用额度。

## F. 分区、撤销与一致性

模拟两个分区，各自运行已知且未过期的局部授权。验证：

- 原 Memory 本地读写继续，不需要网络；不可达不能被说成已删除。
- 本地撤销先持久化，阻止本地新发送/准入；远端未获知的窗口如实报告。
- 远端获知或授权到期后拒绝；普通重启不能撤销这条撤销记录。
- 同序号不同联系人正文保留冲突；首次连接不能宣称已知全网最高序号。
- 跨分区不承诺即时撤销、全序消息或全局强一致性。
- 恢复连通后有界刷新路由、原样补发与去重，不能全网同步总名册。
- 两边各自完成有限补副本时，按 provider/epoch/lease 合并加法事实，
  不用一个 last-writer-wins 总表删除另一边唯一可读副本；额度预先
  分区或绑定目的地，不能两边花同一个无限续租令牌。
- 两个预先获准的独立写者/feed 在分区期间分别追加 B 未见过的消息；
  恢复后从旧 `K_B` 合并枚举结果，两个有效成员都恰好出现一次。
  重复导入/重放幂等，不能用最后一个 head 覆盖另一条合法追加；同一
  写者/位置冲突必须显式保留或拒绝，不能偷偷选择一条或发明全局顺序。
  枚举修复仍须验证每条原 attempt/grant 和有限写者范围，不因合并扩权。
- 丢失节点持久状态必须换 epoch 并重新授权，不能冒充普通重启。
- 逐出联系人缓存不能删除仍被活跃授权依赖的高水位/撤销记录；
  旧备份或安全检查点丢失进入 freshness_unconfirmed，拒绝凭旧授权
  恢复发送。缓存刷新不等于已经确认资源节点当前状态。

真实跨地域阶段至少覆盖三个独立地区/网络故障域，记录证据来源，
测量 RTT、断网、丢包、区域失效及恢复期间的成功率和积压。
目前没有采购或部署该资源，因此这一阶段必须保持“未运行”。

## G. NAT、反滥用与升级

真实跨网测试须分别覆盖 NAT 后出站 HTTP 客户端、IPv4/IPv6、UDP
不可用、直接连接失败后的授权邮箱回退、移动换网和入口失效。
可选 ICE/TURN 不得成为唯一中心依赖，失败不解除授权或 E2EE。
回环测试不能冒充 NAT 穿透；本阶段不修改本机代理、防火墙或私人配置。

攻击用例包括真实生成的多身份、偏置 ID、同网段大量路由广告、恶意
引导提供围困视图、重放/过期/错目标/错域签名、DNS 重绑定、重定向
和指向私网/云 metadata 的地址。测试资源受控且仅针对合成目标。
必须同时报告可达性退化；“没有越过配额”不等于已彻底解决 Sybil。
有限敌手模型、最低可达性与延迟门槛、来源分组的真实证据限制，均按
增长合同执行。双查找 lane 共享总预算且给另一条路径保留调度份额；
验证慢而有效的签名响应、同来源换钥以及诚实 NAT 共址的误伤。
共享候选两条来源只发一次实际 RPC，结果不得被首次引介者独占。
同来源桶被稳定恶意邻居占满时，显式新诚实介绍仍能在总预算内临时
探测，不要求先进入 active 桶；任意广告不得借此绕过来源限额。

两种版本并存时，协商必须绑定签名 profile，不得降级为明文或绕过
许可。旧 Memory 原 bytes/ID/proof 不变。没有兼容 profile 时明确拒绝；
不得强制全网更新、自动安装同行软件，或由某个 Agent 决定协议版本。

## 证据输出与停止条件

每次运行固定并记录 source SHA、运行环境、种子、配置、节点角色数、
实际数据/模拟数据区别、耗时、失败和跳过，以及指标原始分布。
输出报告不能包含真实记忆、身份私钥、邀请、私人日志或机器配置。

以下任一情况阻止对应能力声明：

- 生产算法读取全网 oracle、依赖唯一引导/authority，或者每次加入全网同步。
- 加资源后新增节点不承担实际负载，本地占用随全网成员/对象线性增长。
- 需要原发送端在线才能修复，或一份 ACK 被当作多故障域持久性保证。
- 仅凭 `K_m` 对象读取就宣称冷收件成功，向 B 注入消息产生后的 ID/页/
  地址/成员索引，或把枚举缺口当空邮箱并提前推进完成游标。
- 队列/暂存/重试越界，额度先释放后删除，或者过载仍返回保存成功。
- 修改原 Memory，放宽依赖分享边界，或让发现/消息授予权限。
- 把模拟节点、模型名称标签或加速时钟当真实 AI/跨区域/72 小时验收。

先完成整体架构及本计划的有界审阅，再按功能里程碑实施。
当前这份文档没有新增测试通过数，也没有改变公开 Release 的能力声明。
