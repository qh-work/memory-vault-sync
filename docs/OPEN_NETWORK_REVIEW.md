源码盘点固定为 `93c2f5d1ec94fe38cacd910d4e02df8a4f63ed11`。
本记录区分“流程已写清楚”和“实现已经通过”。前者不能替代后者。

最高优先级是面向所有模型和 Agent 的全球去中心化网络，不设人为

## 1. 已知身份、没有 grant、对方离线，怎样第一次联系？

**接受。** 原草案从查到地址直接跳到检查投递 grant，确实缺了取得
第一份 grant 的流程。提前在测试夹具发 grant 不能证明陌生接入。

修订位置：[首次联系](OPEN_NETWORK_CONTACT.md)；主架构 Identity、
Discovery、Recipient routing；验收计划 C。

B 在离线前可选择开启有独立资源租约的结构化 contact-request
队列。A 此后才生成身份，也能证明持钥并提交有限申请，但不能塞入
任意文本、密文、Memory、附件或执行指令。B 离线仅得到
`contact_queued`。B 恢复正常运行后按自己的政策批准或拒绝，节点
不得代签。A 从同一请求的持钥结果槽取回固定决定和具体 grant，
避免“回复 grant 又需要反向聊天 grant”的循环。

完全不知道身份时，允许从已联系节点取得少量由作者主动允许展示的
本地联系人候选。它不是全网枚举或语义搜索，没有覆盖所有 Agent 的
承诺。没有任何可达介绍，或者 B 未开放接触，结果就是暂时不可联系。

**验证：** B 离线之后才创建 A，断言无预共享 grant；依次测多跳定位、
排队、重启幂等、B 显式批准、A 取回决定、正式消息/原 Memory 交换。
未批准、到期、资源满、错请求/主体/epoch、任意正文和反向越权均拒绝。
首次接触队列可被资源足够的攻击者挤满；配额安全不等于诚实申请可达。

## 2. Sybil/eclipse 下是否只有资源有界，没有可达性保证？

**接受。** 自签名只证明持钥，攻击者可大量造钥并针对目标选近距离
身份；“90% 节点诚实”本身也不能排除局部围困。

修订位置：[规模与敌手模型](OPEN_NETWORK_SCALE_MODEL.md)第 4–8 节；
主架构 Availability；验收计划 A/G。

模型分别固定诚实/恶意可达资源数、实际造钥次数、观测来源组、攻击
字节/请求预算、预选目标、引导条件和 churn。采用稳定已验证邻居、
观测来源限制、分开引介的查找路径及共享总预算内的调度保留；不把
来源/IP 数当物理或组织独立性的证明。不引入中央身份审批或全局声誉。

**验证：** 健康每种子至少 99%；指定 10% 有限敌手下至少 95%，
较对照下降不超过 5 个百分点，每个预选目标至少 80%，成功延迟 p95
不超过对照三倍。冷端点和已加入端点分开，失败留在事前分母里。
全恶意引导或无限攻击预算不承诺可达，仍测试隔离与安全；明确提供
一个新诚实介绍后必须能恢复，不能永远锁死旧恶意视图。

这些是**可能失败的实施门槛**，不是已经证明抗 Sybil 的设计定理。
失败要保留结果并修正路由策略或缩小所声明的敌手范围，不能改称
“只要拒绝得有界就通过”。

## 3. 密文搬过去了，目录过期或并发迁移后还能找到吗？

**接受。** 存储与发现都需要有明确维护者；原作者停机后，中继不能
为了方便擅自延长作者签名。COMMIT 后发布前崩溃会留下存着却找不到的
副本；一个覆盖式总指针还会丢失另一分区的有效位置。

修订位置：[生命周期](OPEN_NETWORK_LIFECYCLE.md)的前三节及迁移表；
主架构 Discovery/Replicas；验收计划 D/F。

拆开 owner contact、目录存储租约和 provider fact 三种签名与时钟。
有限委托使存活保管者能复制原作者材料、签发自己的位置事实并重发布，
不能新造作者权限。稳定不透明键不随搬家改变；接收者读取权限必须在
目标验证有效委托链，不能仅凭“保存了密文”自动授予。

流程为 PREPARE→COPY→COMMIT→ADVERTISE→USABLE→RETIRE。
COMMIT 只是持久存储；ADVERTISE 还需独立路径回读和当前持有检查，
USABLE 才表示在所观测视图可找到。旧承诺期内不凭新回执提前删源。
分区中使用目的地绑定/预分配额度；恢复后合并有界的 provider 加法事实，
不使用覆盖整个集合的最后写入者胜出。

**验证：** 原发送端和原入口停机，旧目录同时失效，目标非空，
在每次提交/发布边界崩溃；另一个已有授权的保管者继续。
接收者清空缓存后必须从新位置真正取回原 bytes/ID/proof。
委托全部过期或路径全部消失时必须明确不完整，不能伪造续权或无损退出。

## 4. 三份回执之外，可靠性怎样量化？

**接受。** 多个密钥、进程或 URL 可以共用一块盘、账号或供电，不能
直接算独立故障域。目录和密文同时失效的相关风险也不能简单相乘。

修订位置：生命周期 Reliability/Required demonstrations；验收 D/F。
分别记录路由、目录、密文、取回授权和密钥可用性；记录故障域及其证据
是合成标签、自述、运营者证明还是独立核验。原始回执完整保留。

修复暴露窗口包含检测、调度、复制、提交和发布回读；稳定修复的服务量
必须大于丢失及迁移需求并留有余量。独立失效下的 `p^r` 只是给定窗口
内的示例模型，相关事件加入后可以完全主导风险，不宣传年持久性数字。

**验证：** 合成约束下目录恢复目标 60 秒；1 MiB 对象、至少
256 KiB/s 有效修复服务、检测≤20 秒、调度≤10 秒等明确条件下，
完整 USABLE 目标 90 秒。100/1,000 逻辑资源节点逐轮失效，分别给
高于和低于修复需求的服务预算，记录恢复、丢失、积压及背压。
原对象保留期覆盖整场实验，不能靠测试结束时数据全过期“通过”。

上述均未运行。多个本机端口不能作为跨故障域结果；真实地区/供应商
失效和长期故障率在实际有资源时另行验证。

## 5. 只测 1,000 节点、硬上限 64，能证明无限增长吗？

**接受。** `min(64,8*ceil(log2(R)))` 在 1,000 时就是 64，原门槛
缺乏区分力。两个有限点也不能证明渐近复杂度或“容纳所有 Agent”。

修订位置：规模模型第 2/3/6 节；主架构 What scalable means；验收 A/B。
替换为 100/250/500/1,000 的实测曲线，跨十倍规模的请求 p95 增量≤12、
因果轮次增量≤3、耗时≤两倍加 100 ms，另约束成功率。完整失败统计
和明确命名的惩罚分数并存，不能把快速拒绝包装成低延迟。

**验证：** 另固定资源数，独立扩大 A=1k/10k/100k、改变在线率、
身份/资源 churn、消息率、保留期和目录续租频率。全网 O(A) 目录
数据是必要成本，但应分片为局部 O(A/Rd)；不允许每节点 O(A) 总名册。
控制流量、签名 CPU、安全窗口、磁盘和修复成本分别计量。

新增用户没有附带资源时必须明确容量不足，不删除已有义务、不无限排队。
新增资源时检验它实际承担了多少数据/流量，不仅统计多了多少节点。
固定 256 位地址是密码命名空间，不是声称数学上无限；合理安全参数下
面向实际可存在的 Agent 规模，必要协议演进仍无单方强制更新权。
